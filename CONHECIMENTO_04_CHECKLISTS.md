# Checklists operacionais

Use estes checklists como roteiro. O agente não deve marcar itens como concluídos sem confirmação explícita do usuário.

## A. Antes da montagem
- [ ] Confirmar quem é o responsável técnico do evento.
- [ ] Confirmar se houve alteração recente em equipamentos, cabos, softwares ou rede.
- [ ] Verificar visualmente alimentação e estado geral dos equipamentos.
- [ ] Confirmar que os equipamentos necessários estão disponíveis.
- [ ] Não realizar atualização de software, driver ou firmware imediatamente antes do evento sem plano aprovado.

## B. Vídeo
- [ ] Verificar visualmente os cabos SDI nas câmeras.
- [ ] Verificar visualmente as conexões na DeckLink Duo 2.
- [ ] Abrir o template padrão no vMix.
- [ ] Confirmar imagem limpa nos Inputs 1 e 2.
- [ ] Confirmar que o retorno local está funcionando, se aplicável.
- [ ] Verificar enquadramento e exposição com o operador autorizado.

## C. Áudio
- [ ] Confirmar que a Midas M32 está operando.
- [ ] Confirmar sinal nos canais necessários.
- [ ] Confirmar recepção no LUNA.
- [ ] Confirmar saída estéreo do processamento, conforme o fluxo local.
- [ ] Confirmar sinal na Behringer UMC202HD/entrada de áudio selecionada no vMix.
- [ ] Conferir áudio na transmissão de teste ou monitoramento autorizado.

## D. Saídas de transmissão
- [ ] Conferir o destino YouTube no vMix.
- [ ] Conferir o destino Restream no vMix.
- [ ] Comparar os perfis com a configuração aprovada e vigente.
- [ ] Não exibir, copiar ou compartilhar stream keys.
- [ ] Confirmar conectividade e estabilidade de upload.
- [ ] Confirmar operador responsável por iniciar as saídas.

## E. Validação externa
- [ ] Verificar YouTube em dispositivo independente.
- [ ] Verificar Instagram/Restream, conforme o fluxo aprovado.
- [ ] Verificar áudio.
- [ ] Verificar vídeo.
- [ ] Verificar sincronismo.
- [ ] Confirmar que os destinos esperados estão recebendo sinal.

## F. Durante o evento
- [ ] Monitorar indicadores de áudio no vMix.
- [ ] Monitorar status de cada destino.
- [ ] Observar fluidez do vídeo.
- [ ] Evitar mudanças estruturais.
- [ ] Registrar horário e sintoma de qualquer incidente.
- [ ] Acionar responsável técnico para ações de alto risco.

## G. Encerramento
- [ ] Encerrar as saídas conforme o procedimento local aprovado.
- [ ] Confirmar que os destinos encerraram corretamente.
- [ ] Salvar sessão/projeto se aplicável.
- [ ] Registrar incidentes, alterações e soluções.
- [ ] Anotar pendências para manutenção antes do próximo evento.

## H. Verificação de incidente
- [ ] Registrar horário em que começou.
- [ ] Registrar o que parou de funcionar.
- [ ] Registrar o que continuou funcionando.
- [ ] Registrar mensagens de erro literalmente.
- [ ] Registrar cada ação executada e seu resultado.
- [ ] Não registrar senhas, tokens ou stream keys.
